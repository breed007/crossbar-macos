# Crossbar v0.7 release spec

**Status:** In progress · **Version:** 0.7.0 · **Target:** macOS 14+ · **Drafted:** 2026-11-12

## Summary

v0.7 tells you when a new version of crossbar is out, if you ask it to. It checks
GitHub's latest release once a day, shows a line in the popover when there's a newer
one, and sends you to the release page or the Homebrew command. It never downloads
or installs anything itself. Three small items deferred from the 0.6.1 review come
along. Switchback 0.7 gets the same update check (see its own v0.7 spec).

## Why now

1. **Nothing tells a direct-download user about a fix.** 0.6.1 fixed a Focus swap
   that could leave the Mac offline. Someone who installed the dmg won't know.
2. **Homebrew users are covered, everyone else isn't.** `brew upgrade` already
   updates the cask. The check has to fit both without fighting Homebrew.
3. **The 0.6.1 review left four items for later.** Three are small enough for 0.7.

## Decisions

- **Notify only.** Crossbar never downloads or replaces itself. Installing an app
  that ships a root helper is security-sensitive work, the standard tool (Sparkle)
  would be the first third-party dependency, and a self-update would leave Homebrew's
  record of the installed version wrong. Opening the release page leaves the checks
  to Gatekeeper and notarization.
- **Off until you say yes.** The README promises no network calls. The check is
  opt-in, the first popover asks once, and the Privacy section says exactly what is
  contacted and what is sent.
- **One request, nothing about the Mac.** A GET to
  `https://api.github.com/repos/breed007/crossbar-macos/releases/latest` with an
  ephemeral session (no cookies, no cache), a fixed User-Agent (`Crossbar`), and no
  version, user, or device details. GitHub sees an IP address, like any web request.
- **Homebrew installs get the Homebrew command.** If a Caskroom folder for crossbar
  exists, the update line shows `brew upgrade --cask crossbar` with a Copy button
  instead of opening the release page.
- **IT can turn it off.** A managed `DisableUpdateCheck` preference (MDM) turns the
  check off and hides the controls.
- **Two copies.** Switchback gets the same logic in its own repo. A shared package
  waits for a third app (rule of three).
- **0.7, not 0.6.2.** A new feature that changes the privacy promise is a minor
  release.

downloads or installs, a beta channel, and notifications for updates.

## Features

### U1: Opt-in daily update check

- Preference `CheckForUpdates`: unset (never asked), on, or off.
- While unset, the popover shows one row above the footer: "Check GitHub for
  crossbar updates once a day?" with **Turn On** and **No Thanks**. Either answer
  hides it for good; Settings can change it later.
- When on, crossbar checks at launch and then hourly whether 24 hours have passed
  since the last check. A failed check waits for the next window and says nothing.
- The response must be a release: `tag_name` like `v0.7.1` and `html_url` under
  `https://github.com/breed007/crossbar-macos/releases/`. Anything else counts as
  "no update". Crossbar never opens a URL that fails this check.
- Versions compare numerically by component (0.10.0 is newer than 0.9.2). A tag that
  doesn't parse is ignored.
- The newest version seen is stored, so the line survives a relaunch and disappears
  once the installed version catches up.

### U2: Update line in the popover

- When a newer version is known, a line above the footer reads
  "crossbar 0.7.1 is available".
- Clicking it opens the release page, or, for a Homebrew install, an alert with the
  `brew upgrade --cask crossbar` command and **Copy Command**, **Release Notes**,
  and **Cancel**.
- Homebrew install: `/opt/homebrew/Caskroom/crossbar` or `/usr/local/Caskroom/crossbar`
  exists.

### U3: Settings

- A new **Updates** section: "Check for updates once a day" checkbox and a
  **Check Now** button.
- Check Now runs right away, whether or not the checkbox is on, and says the result
  in place: "crossbar 0.7.0 is up to date.", "crossbar 0.7.1 is available.", or
  "Couldn't reach GitHub."
- With the managed `DisableUpdateCheck` set to true, the section shows "Update checks
  are turned off by your organization." and nothing else, the popover never asks,
  and no request is made.

### R1: Retry once when the helper quit

The helper quits after 60 idle seconds. A request that arrives as it exits gets a
"connection interrupted" error and falls back to sudo (or fails without a sudo
rule). On `XPC_ERROR_CONNECTION_INTERRUPTED`, `HelperClient` retries once.
Setting a service to the state it's already in is harmless, so the retry is safe.

### R2: Popover scrolls

With more services than fit on screen (many VPN profiles), the service list scrolls
inside the popover. The popover's height is capped at the screen's visible height
minus a margin; the title and footer stay put.

### R3: Hidden-interface cache

`HiddenInterfaces` caches the I/O Registry lookup by BSD name for the life of the
process, so it goes stale if a different adapter later gets the same name. Clear the
cache on each network-change notification.

## Risks

- **GitHub rate limits.** Unauthenticated API calls allow 60 an hour per IP. One a
  day per Mac is far below that, even behind a shared office IP.
- **Trust in the response.** The JSON comes over TLS from api.github.com, and only
  a version number and a URL under our releases path are used. Nothing is executed.
- **Untested hands-on:** the first-run row and Homebrew detection on a real Homebrew
  install.
