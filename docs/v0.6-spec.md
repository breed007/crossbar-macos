# Crossbar v0.6 release spec

**Status:** In progress · **Version:** 0.6.0 · **Target:** macOS 14+ · **Drafted:** 2026-10-04

## Summary

v0.6 fixes the v0.5.0 helper setup bug, then makes toggling safer and easier to
read: Crossbar warns before you disable the service carrying your traffic, shows a
service settling after you turn it on, and says what changed in the menu bar.
Settings move into a small window, the popover works from the keyboard, and
Shortcuts and Focus can turn services on or off.

## Why now

1. **The v0.5.0 setup button probably fails.** Switchback's v0.5 milestone 1 found
   that `SMAppService.register()` for a daemon throws "Operation not permitted" on
   macOS 27 even when registration succeeded into `.requiresApproval`. Crossbar calls
   `register()` with a plain `try`, so "Set up passwordless toggling…" most likely
   shows an error instead of the approval steps. Nobody ran that path on a signed
   build before v0.5.0 shipped.
2. **Homebrew users are on 0.3.0.** The cask was never bumped for 0.4.0 or 0.5.0,
   and it has no `uninstall` stanza for the helper.
3. **Switchback moved ahead.** It has a test suite, a debug harness for signed
   builds, router fallback, an audit log, native hidden-interface detection, menu
   bar feedback, and App Intents. Crossbar can adapt most of that.

## Decisions

- **One release.** The 0.5.1 fixes ship inside 0.6.0.
- **XcodeGen.** The hand-written `pbxproj` is replaced by `project.yml`, matching
  Switchback. The generated project is ignored.
- **No ⌘-number shortcuts.** In Switchback a wrong ⌘3 picks the wrong location.
  Here it turns off a network interface. The popover gets arrow keys and Space.
- **Automation owns no rules.** Crossbar provides actions to Shortcuts and Focus.
  The user writes the rule in Apple's tools. Every automated change is announced.
- **Still two copies of the helper.** Crossbar and Switchback each keep their own.
  Extract a package when a third app needs one (rule of three).

## Features

### F1: Helper setup fix and hardening

- `register()` that throws while the status is `.requiresApproval` counts as
  success, and the user sees the approval steps.
- Approval opens Login Items with `SMAppService.openSystemSettingsLoginItems()`
  instead of a URL scheme.
- `ToggleRouter` falls back to Backend A (`sudo -n networksetup`) when the helper is
  installed but can't be reached. It does not retry when the helper itself reports
  a failure.
- The helper refuses a malformed service ID before it touches preferences or the
  log (Switchback found a newline in an ID could split an audit line), runs all
  work on one serial queue, logs every change to the unified log (caller UID,
  service ID, on or off, result; never names), and exits after 60 idle seconds.
- The Homebrew cask moves to 0.6.0 and unloads the helper on uninstall.

### F2: Native hidden-interface detection

The read layer runs `networksetup -listallnetworkservices` to hide services that
System Settings hides. Those are the internal Apple silicon USB-C interfaces
(usually en4 to en6), and their drivers carry `HiddenConfiguration = Yes` in the
I/O Registry. Crossbar checks that flag directly, as Switchback does. The read
layer no longer starts a process, so a refresh runs synchronously.

### F3: Preview before disabling the active route

Turning off the service that carries traffic is the one toggle that can surprise
you. Before it happens, Crossbar predicts the result from the service order and
which other services have a router:

- Another service can take over: "Traffic will move to Wi-Fi (MI6)." This
  confirmation can be turned off.
- Nothing else is connected: "You'll go offline." This always asks.
- A remote session is active (SSH or Screen Sharing): an added warning that the
  session may drop. This always asks.

Dormant services never ask. Automations never ask (see F8).

### F4: Settling state after turning a service on

After you turn a service on, its row shows "Connecting…" until it gets an address
or 20 seconds pass. This replaces the yellow "not connected" dot that made a
successful toggle look like a failure.

### F5: Menu bar feedback and optional network name

- After any toggle, the menu bar shows the result next to the icon for about three
  seconds ("Wi-Fi off").
- An optional **Show Network Name in Menu Bar** setting keeps the active network's
  name there: the SSID when Wi-Fi carries traffic, otherwise the service name.
  Names longer than 16 characters are truncated.

### F6: Settings window

**Settings…** in the popover opens a window with Launch at Login, Show Network
Name in Menu Bar, the F3 handoff confirmation, and the helper's status with Set Up,
Open Login Items, and Remove buttons. The popover footer keeps Set Up Passwordless
Toggling… until the helper is enabled, then just Settings…, Network Settings…, and
Quit.

### F7: Keyboard control in the popover

Up and Down move a highlight between rows. Space or Return toggles the highlighted
service, through the same F3 checks. Escape closes the popover.

### F8: Shortcuts, Spotlight, and Focus

- **Set Network Service:** turn a chosen service on or off.
- **Get Network Service:** returns whether a service is on, connected, and carrying
  traffic, for Shortcuts conditions.
- **App Shortcuts** phrases for Spotlight and Siri.
- **Focus filter:** choose services to turn off and services to turn on when a
  Focus starts. Both lists default to empty, so what macOS sends when a Focus ends
  changes nothing.
- Automations go through `ToggleRouter`. Backend A never prompts, so a Focus can use
  either backend. A change that's already in effect does nothing. Every automated
  change posts a notification, including the F3 prediction when the active route
  was turned off.
- The intents live in the app target, so the helper's single-identifier pin covers
  them. The rules live in a plain `AutomationToggle` type that tests drive with
  fakes.

in `/Applications`) and driven from Terminal through the debug flags.

| Tests | 15 unit tests; two planted router bugs each fail the suite |

**Findings**

- A registration attempted while an earlier request is still pending (here, after
  `register` → `unregister` → `register` without approving) throws "Operation not
  permitted" **and stays unregistered**, unlike the first registration, which lands
  in `.requiresApproval`. BTM shows the app as "pending authorization" and the
  daemon as "disallowed". It clears once the user turns Crossbar on in Login Items.
  The setup flow now points at Login Items on any registration failure instead of
  showing the raw error.
- The Developer ID certificate in use is now "404 Cybersecurity LLC (YA83Q8FTH3)".
  The pin checks the team, so nothing changes.

## Milestone 2 results (2026-10-04)

- **F2.** The I/O Registry `HiddenConfiguration` check gives exactly the same service
  set as `networksetup -listallnetworkservices` on this Mac (en4–en6 hidden, the
  other four shown). `StatusMonitor` no longer starts a process and refreshes
  synchronously. Its builder is static (`readServices`) so Shortcuts and the debug
  flags can read services without a live monitor.
- **F3 logic.** `RoutePrediction` picks the next enabled service with a router in
  service order (not the display order, which is sorted by category). On this Mac,
  with Wi-Fi powered off, disabling Thunderbolt Ethernet predicts "offline", which
  matches `scutil --nwi` (only en7 is reachable).
- **Remote sessions.** SSH logins come from utmpx records with a host. Screen Sharing
  is a running `screensharingd`, found with the `KERN_PROC` sysctl: `proc_name`
  returns nothing for root-owned processes, so it would never have seen it.
- 22 unit tests.
